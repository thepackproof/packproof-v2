## Runner guarantees and failure handling

`infra/mobile-intake-migration.mjs` requires the fixed current/session owner `packproof`, that owner for `schema_migrations`, the expected hosted source and unchanged durability mode. It validates every existing migration checksum and permits only missing 067/068. It refuses checksum adoption, unknown migrations and mismatched source bytes. A partially completed 067 followed by failed 068 can be retried forward without rewriting the accepted 067 receipt.

The temporary login uses an unpredictable name/password, a SCRAM verifier, NOINHERIT, no superuser/createdb/createrole/replication/bypassrls privileges, a two-connection limit and a 15-minute expiry. Its separate connection explicitly assumes only the fixed owner role, then verifies both `current_user` and the distinct `session_user`. The inherited runtime secret callback is removed from the child environment so it cannot substitute master credentials for that login. TLS and durability settings remain unchanged. The existing `dist/db/migrate-cli.js` performs the migration and policy-durability verification; its raw stdout/stderr is suppressed. Statement/lock/subprocess deadlines bound execution.

Cleanup waits for the child to close and attempts to drop the temporary login whether grants, verification or migration fail. New objects must belong to the fixed owner. Cleanup never uses `DROP OWNED`, `REASSIGN OWNED`, schema deletion or runtime-role changes. A cleanup failure is a failed operation with an explicit temporary login identifier in the bounded receipt; the login still expires. If an infrastructure kill prevents cleanup, inspect the recorded `pp_intake_migrate_*` roles and their expiry through the controlled operating path before continuing.

Successful postflight verifies exact 067/068 executed-byte receipts, complete schema compatibility, fixed owner for all three new tables, each of SELECT/INSERT/UPDATE/DELETE for the existing runtime owner, and unchanged durability policy. No additional runtime grants are needed for the verified owner configuration. A different current role or table owner fails closed and requires a reviewed migration-path update.
