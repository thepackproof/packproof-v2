# API implementation boundary

The generated [partner OpenAPI contract](../../backend/partner-openapi.json) describes the retained organization/Proof API and the actual records increment. Run `node scripts/check-records-api-readiness.mjs` to compare its generated operations with mounted source routes. This static check confirms source/description alignment; behavior, production activation and external acceptance require their own evidence.

| Capability | Implemented surface | Boundary |
| --- | --- | --- |
| Canonical record creation and lookup | Existing `/v1/partner/proofs`, resolve/list/read and explicit source bindings | Preserves Proof ID, operator assignment, environment and permanent scoped source identity. Creation returns an operational revision and authenticated portal locator. |
| Operational record review | Additive partner record/timeline/evidence/requirements reads; revision-protected metadata, lifecycle, amendments, relationships and evidence links | Operational view is separate from a prior frozen signed inventory. Service credentials gain no personal attestation or human waiver authority. |
| Durable normalized source observations | `/v1/partner/ingestions` and `/v1/partner/operations/{operationId}` | Existing authorized source-bound Proofs; max 100 events/256 KiB. Canonical receipts preserve matching duplicates and changed-content conflicts. Assurance stays organization-submitted. Operation ownership includes the exact originating credential and delegation. |
| Requirements and human review | `/me/records/{proofId}/requirements`, waiver and review commands; scoped issue actions | Current human membership and operational revision required. Waivers require OWNER/ADMIN and a reason. Missing evidence does not establish physical loss. |
| CSV setup and repair | `/me/records/imports` preview/receipt/commit/template/corrections/limits | Human-only one-time import; max 2 MiB/1000 rows. Original version/digest, mapping, source time zone and row outcomes are retained. This is not a partner CSV endpoint or recurring connector. |
| Portal retrieval | Human context/list/detail/attention/exports routes | Current organization, environment, role and location scope precede search/counts/results. Child timeline/evidence pages use opaque scope-bound cursors. |
| Originals and core package | Human record artifact blob and finalized core package routes; retained partner package/envelope contract | Current access is checked while streaming. A finalized core package covers its frozen inventory; it does not silently sign later operational annotations. |
| Source recovery | Human connection inventory, pause/resume/test/reconcile and operation resources; partner read-only connection inventory | Source checks require an explicitly registered and validated adapter. Authentication alone cannot establish freshness. Automatic connector capability remains a pilot gate. |
| Workspace onboarding | Human workspace requests and context, existing organization administration | Verified contact/recent sign-in and explicit rollout flags; registration creates a disabled merchant awaiting entitlement, not an automatically activated production workspace. |
| Integration diagnostics | Effective `/limits`, scoped `/issues`, narrow `audit:read` audit events, webhook delivery/replay | Metadata only; no credentials, signed URLs or raw provider/customer payloads. Replay requires current destination/credential/delegation ownership and preserves event identity with a fresh dispatch timestamp. |
| Events and clients | Retained committed event stream, existing signed webhook wire profile, Node/TypeScript and Python candidate SDKs | At-least-once delivery; receiver deduplication and canonical reconciliation remain explicit. Standard Webhooks migration, secret overlap and registry publication are not implied. |

These proposed additive partner paths remain unimplemented in this increment: `/v1/partner/imports`, `/v1/partner/upload-sessions`, `/v1/partner/evidence/{id}/download`, `/v1/partner/snapshots/{id}`, `/v1/partner/exports`, `/v1/partner/shares`, and `/v1/partner/deletion-requests`. Existing human capture, envelope, access-link, account/retention and legacy API routes continue under their own contracts and gates; they are not substitutes for claiming the proposed uniform paths are complete.

The candidate does not yet establish general availability. A real authorized automatic connector, nontechnical task study, independent security review, real PostgreSQL concurrency qualification, load/restore exercises, controlled cohort activation and observation period require observed results. See [RELEASE_GATES.md](RELEASE_GATES.md) for the release decision.
