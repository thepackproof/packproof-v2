# Consented operational observation seam

Migration `045_program_observations.sql` and
`backend/src/analytics/observation-export.ts` implement a bounded source exporter
and append-only client timing intake. Nothing is enrolled by installing or using
PackProof. Importing the mobile/web timing bridge registers no listeners and
sends no requests.

## Governance and runtime API

An operator first provisions a dataset with
`createProgramDataset(db, clock, {key, keyVersion})`. The dedicated analytics key
must have at least 32 bytes and a stable version. Dataset references are random
and generated by the server; merchant, task, event and domain references are
keyed server pseudonyms scoped to that dataset. A pinned key-material fingerprint
and key version stop accidental pseudonym changes: either mismatch stops
collection/export. No raw user, Proof, evidence, media, barcode, order or provider
identifier is stored in the new observation tables or exported.

Authenticated account actions use:

| Function | Input after the account-bound runtime arguments |
| --- | --- |
| `getProgramConsent` | `datasetRef` |
| `recordProgramConsent` | `datasetRef`, UUID `operationNonce`, `decision` (`grant` or `withdraw`), `statementVersion: "capture-timing-study-v1"` |
| `startProgramTiming` | `datasetRef`, UUID `operationNonce`, `clientStartedAt`, enumerated `deviceClass`, `channel`, `taskKind` (`packproof` or `ordinary_baseline`) |
| `appendProgramTiming` | `datasetRef`, server `attemptRef`, UUID `operationNonce`, enumerated `phase`/`outcome`, cumulative `elapsedMs`, `activeMs`, `offlineMs`, `unattendedMs`, optional enumerated `errorCode` |

Consent requires a deliberate account action presenting the exact exported
`STUDY_STATEMENT`. Use an unchecked control. Both account and dataset must match;
another account's consent or attempt reference gives no access. Dataset creation
and `exportProgramObservations` are internal operating functions and must not be
exposed to ordinary authenticated callers as cross-account queries.

Timing starts persist before the measured action. All client observations have
client authority, including a client-reported successful end. They never emit a
server preservation or finalization event. Unknown fields and arbitrary text are
rejected. Cumulative durations are integer milliseconds bounded to 24 hours;
offline time may overlap active/unattended time. Starts are limited to 1,000 per
account/dataset/day and updates to 250 per task. No automatic device fingerprint
is collected; the device class is a bounded self-report.

Same operation/same facts is an idempotent retry. Changing the facts under that
operation returns a conflict, and SQL triggers reject updates/deletes of stored
events. Consent and timing operations serialize on the dataset row, so withdrawal
cannot race acceptance. Withdrawal stops queued/new intake; earlier contributed
observations remain according to the disclosed statement. Attempts bind to the
grant event at their start. A regrant permits new tasks without rewriting prior
consent; old tasks cannot backfill the withdrawn interval. Client starts predating the
current consent or more than five minutes ahead of server time are rejected;
incorrect device clocks can therefore leave missing observations, never invented
timings.

`mobile/src/analytics/timing-bridge.ts` is shared with web. The host supplies an
account-scoped durable timing store, an account-bound API, a current-account
predicate and a cryptographic UUID factory. `start()` checks explicit consent and
persists a start before capture/preflight. `checkpoint()` stores only whitelisted
enums and numbers. `flush()` obtains the server attempt reference, replays the
same operations after lost responses, and removes only the completed timing
journal after acknowledgements. Pending failure/offline records survive transport
loss. Withdrawal deletes unsent study data; it never touches capture media or
the separate completion journal. The host should handle telemetry errors without
blocking preservation of the customer's recording.

`createObservationRouter` mounts at `/study`. It independently authenticates every
request; exposes only own-account consent and timing intake; and has no dataset
creation or cross-account export route. Environment parsing defaults disabled.
Explicit enablement requires `PACKPROOF_STUDY_ENABLED=true`, a dedicated
`PACKPROOF_ANALYTICS_KEY_BASE64`, stable `PACKPROOF_ANALYTICS_KEY_VERSION`, and an
internally provisioned `PACKPROOF_STUDY_DATASET_REF`. It seeds no consent.

The web Account study panel presents the exact statement and an unchecked
agreement control. The station workflow records an opted-in task start before
preflight, phase changes, failures and an end; normal capture makes no study
request without a prior local opt-in. Its IndexedDB journal resumes from the
global recovery owner. Active/unattended fields here classify observed foreground
task windows, not attention or manual effort. Leaving the station closes that
client task as cancelled while canonical upload recovery remains independent.
Native has the tested shared bridge and API method, but its camera/provider hooks
and native consent UI are not yet connected; do not claim native timing coverage.

## Canonical query export and limits

`exportProgramObservations(db, clock, runtime, {datasetRef,start,end,asOf})`
returns a strict `ProgramInput` as `observations`, plus validated `ProgramEvent`
rows, pseudonymous client timing observations, canonical capture starts, and
explicit partial-coverage warnings. Period ends are exclusive and output is
bounded to 100,000 rows per source; a larger period fails instead of silently
truncating a denominator.

- All initialized root/stage uploads in consented windows are included, including
  uncommitted work. Canonical capture starts are a separate denominator, including
  sessions that never initialized an upload. No terminal state is invented where
  the source lacks an authoritative historical timestamp.
- Evidence commit is separate from receipt-confirmed preservation. Server
  preservation/finalization events require canonical durable receipt state,
  matching operation/event hash, and the receipt's original preservation time.
  Delivery-retry time does not replace receipt time.
  Recipient export approval comes only from its immutable approval row, and does
  not establish portal acceptance or reviewer comprehension.
- Failed and unfinished client task starts remain visible. Offline durations are
  kept as client context; they are not silently joined to unrelated canonical
  upload attempts. Unpaired ordinary/PackProof tasks cannot pass paired-effort
  thresholds without governed matching.
- Consent is not merchant qualification or cohort enrollment. A finalized Proof
  is not automatically a usable Proof. Order eligibility, usable quality,
  assistance, reviewer tasks, cost invoices, payments, paid periods and cohort
  enrollment remain missing until separately reconciled accountable sources are
  provided. The export invents no paid customer or successful cohort.

Verification: five database/router tests cover absent/cross-account/cross-dataset
consent, unknown metadata rejection, replay/conflict, SQL immutability, withdrawal,
failed/unfinished task denominators, canonical pending/committed uploads and
private identifier exclusion, key-material changes, withdrawn-interval fencing,
authenticated routes and disabled defaults. Four shared bridge tests cover default opt-out,
lost start/update responses, offline failure, account switching, withdrawal and
local field filtering. Physical-device timings and real study observations are
not established by these tests.
