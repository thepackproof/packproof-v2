# W02-D adversarial evidence classification

This matrix records the implemented software response to five named attack scenarios. Evidence is `backend/tests/adversarial-evidence-boundaries.test.ts`, backed by the real domain commands, media fixture, database constraints, scoped snapshots and signed supplements. The test video is synthetic test input. These tests do not run a visual fraud detector, reproduce physical attacks on parcels, or establish fraud-detection accuracy.

Classification meanings:

- **Detected:** an explicit conflicting digital operation is recognized and rejected, or a bounded software predicate identifies the conflict.
- **Documented:** the record preserves source-attributed observations, byte equality or conflicting statements for authorized review.
- **Unresolved:** the available software evidence does not establish whether the physical event happened or who caused it.

| Scenario | Executed adversarial fixture | Implemented response and classification | Remaining inference boundary |
| --- | --- | --- | --- |
| Label swap | Bind one scanned tracking number; submit another number in the same authorized recording session. | **Detected** reported identity conflict: `SHIPPING_LABEL_CONFLICT` blocks rebinding. Both decoded scan observations remain recorded; the first bound identity remains unchanged. | **Unresolved** whether a label was physically swapped when that action was not recorded/reported. A scanner observation is not independent attestation of package identity. |
| Reused recording | Commit identical fixture bytes through separate authorized sessions; attempt to transplant a session into another Proof; use an inaccessible account's matching recording as a source. | **Detected** session/Proof transplant is rejected. **Documented** digests allow an authorized viewer to observe byte equality in records they can access. The unrelated account's Proof/source IDs are withheld and its snapshot access is denied. | **Unresolved** why bytes match and whether reuse is deceptive. There is no automatic cross-account reuse search or duplicate/fraud verdict. A new authorized session does not independently prove camera-origin freshness. |
| Similar-item substitution | Create a user-marked identifier chapter and ask whether it proves the same physical item or authenticity. | **Documented** chapter label and author remain `USER_MARKED_OBSERVATION`; order title remains a participant statement. Unsupported identity/authenticity questions return `NOT_ESTABLISHED` with no citations. | **Unresolved** physical identity, substitution and authenticity. Similar appearance, a matching identifier, a valid signature and byte integrity cannot authenticate an object. |
| Reopening after recording | Try changing a registered session's digest and a committed evidence row; append a later seller statement reporting reopening. | **Detected** digital replacement: `CAPTURE_RECORDING_CONFLICT` and SQL immutability block rewritten bytes/digests. **Documented** later attributed statement is appended without changing the frozen manifest. | **Unresolved** unobserved physical reopening after the camera stopped. Continuous capture within a recording is not a claim of continuous custody afterward. |
| Contradictory return | Finalize outbound recording, recipient receipt and return-packing recordings; append buyer and seller statements that disagree; mark an observed difference and request a fraud verdict. | **Documented** both attributed statements and original source references remain in signed supplement history. Comparison remains a manual user observation with explicit limitations. `FRAUD_CONFIRMED` is rejected as an invalid comparison state; assistance abstains from assigning fraud or liability. The frozen outbound manifest is unchanged. | **Unresolved** which statement reflects physical reality, whether damage/substitution occurred, or which party bears responsibility. Contradiction is preserved for review, not resolved by the software. |

Every digest comparison in the suite uses records already authorized to the caller. The negative test deliberately creates another account with the same fixture bytes and confirms that equality does not expose that account's recording identity. No cross-account duplicate index, hidden lookup, or accusation is introduced.

The primary capture disclosure remains explicit: an authenticated participant used an authorized capture session, while camera origin is not independently attested and a compromised device may inject media. Structured assistance provides source-backed lookups and abstains on unsupported physical or liability claims. Comparison wording states that matching identifiers are not authentication and observed differences are not findings of fraud or liability.

W02-D's software scenario coverage is implemented by the five executable cases. The unresolved classifications are intentional epistemic limits, not claims that these physical attacks were detected. Real merchant/reviewer evaluation, physical attack rehearsals and any future detector's independently measured precision/recall remain separate evidence requirements. No overall fraud-free, authentic or unbroken-custody badge is justified by these tests.
