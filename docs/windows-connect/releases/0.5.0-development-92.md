## Operator workflow

1. Launch PackProof Connect and choose where the sales system saves orders. The preview identifies supported fields and shows a sample order. Empty sources can be saved now. An operator can add another location, reuse a location or skip an optional step.
2. Select the warehouse, packing, shipping or delivery folders that apply. The scoped PackProof Partner API can also supply upstream orders. Choose a separate destination for finished proofs.
3. On a compatible deployment, review the source scope in the browser and approve collection. Connect resumes automatically. The service continues collecting with the dashboard closed.
4. Open the order in the desktop or browser dashboard, or open a completed local revision's `summary.html`. The HTML, structured order record, manifest and original evidence form the local proof package.

## Production and compatibility

The high-severity dependency checks for backend, web and mobile are blocking promotion. The reported picomatch versions were already present in those lockfiles. GitHub lists no patched version for [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf). The protected Windows production signing configuration is also unavailable. The current development installer and privately built release components do not activate multi-source collection against the current customer service.

Local folders, authorized UNC locations and the scoped PackProof Partner API are implemented. Direct generic SFTP, object-storage listing and database-change subscriptions are outside this candidate. Named vendors require customer-authorized access, the actual product/version, representative files and recovery evidence. The reader register covers 17 X12 and 10 EDIFACT synthetic profiles, alongside delimited, fixed-width, spreadsheet, document, label, XML and JSON formats. Folder inputs have per-file and per-directory bounds of 2 MiB and 10,000 entries, with up to 24 sources per installation.

A physical Windows 11 reboot, live Cognito consent, Narrator, a customer's own share permissions and an uncoached first-time operator remain open qualifications.

## Recovery

Restore the approved destination's service access after an outage. The writer keeps the prior complete revision readable and retries queued work. For a cold restore, stop the service, retain the entire protected Windows channel directory, machine key context, filesystem permissions and proof destination, and start one compatible writer. Keep the schema compatible with committed revisions when rolling back a service image. Use the validated compatible bridge or a forward repair. Cross-machine encryption-key recovery remains unqualified.
