# Qualification gates and external dependencies

Engineering status and claim eligibility are separate. G0 means isolated and contract-safe; G1 an executable slice; G2 measured physical/technical feasibility; G3 frozen blind evaluation plus security/privacy review; G4 consented pilot with usability/cost/operations; G5 eligibility for separately authorized release. None grants production authorization by itself.

| Track | Evidence still requiring physical, independent or specialist access |
|---|---|
| F01 | 240-label/60-carton optical screening, actual same-content copies and transfers, cross-phone S24 Ultra/A16 plus other Android/iPhone profiles, independent rare-error trials |
| F02 | Real Android/iOS key/platform assertions and recorder/recovery tests; fragments safely exposed by actual native recorder |
| F03 | Independently labeled ordinary packing corpus, occlusion/swap cases and blinded reviewer study |
| F04 | Measured unchanged/changed cartons, calibrated scale, viewpoints, physical geometry error; reconstruction software alone does not satisfy metrology |
| F05 | Authorized real cross-leg examples including new cartons, same-model swaps, copied stickers and optional recipients; qualified OCR/physical/condition channel evidence |
| F06 | Dedicated device/exposure safety review and real replay/print/display/injection attacks on held-out profiles; no torch experiment on ordinary users |
| F07 | Independent sensitive-class corpus and reviewed exports, actual proof benchmarks, qualified cryptographic review before reliance |
| F08 | Matched feature-on/off real phone packing trials, readable details, context, thermal/battery/memory/frame-gap measurements |
| F09 | Two specifically named independent outside witness operators and security review for external reliance; internal test keys are not independent |
| F10 | Correctly consented partner-local data, reviewed privacy accountant/mechanism, initial released aggregate floor of 20 independently enrolled contributors, held-out cross-partner utility |

All observed failures, exclusions, unavailable checks, abstentions and operational failures belong in reported denominators. Physical-instance frames/derivatives remain in the same split; freeze method, thresholds and holdouts before evaluation. No tuning against the locked evaluation set. A zero-error synthetic run supplies no physical-security bound. Approximately 30,000 independent zero-error trials would be needed for a one-sided 95% 0.01% bound; independence must itself be justified.

Every advanced branch still needs executable engineering: actual 3D reconstruction when inputs qualify; real generated valid/invalid ZK proofs; actual local training and secure aggregation. If a dependency cannot be supplied, mark the affected ticket/gate blocked, continue other work, and retain a runnable harness. A rejected scientific hypothesis can be a completed research result but cannot be presented as an implemented customer capability.

No current report in this folder establishes validated hardware profiles, external operator independence, real partner learning benefit, public cryptographic review, patentability, adjudication accuracy or claim outcomes.
