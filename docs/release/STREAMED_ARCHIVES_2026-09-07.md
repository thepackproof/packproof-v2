# Bounded portable archive downloads

The canonical participant and scoped recipient HTTP package downloads use `exportEvidencePackageStream` and `exportDisclosurePackageStream`. They pipe an uncompressed ZIP with data descriptors, CRC32, and incremental SHA-256 checks. Each emitted chunk is at most 64 KiB; the ZIP retains bounded names and central-directory metadata instead of originals or a complete archive. HTTP pipeline backpressure and cancellation propagate to the active source.

The retained product limits are 200 MiB of declared original/selected media, at most 1,000 media sources, 8 MiB per JSON document, and a 220 MiB encoded archive ceiling. Canonical preflight counts root and finalized lifecycle originals together before opening any object. The old Buffer-returning helpers remain only for compatibility and reject archives above 8 MiB. Adapters without a streaming read support only originals at most 5 MiB through the canonical compatibility fallback; production adapters stream.

Canonical reads request the frozen object version. If an older manifest has no version, a database reference is used only when its key, length, and digest exactly match the frozen metadata. A versionless legacy read is permitted only for a key ending in `/committed/sha256-<exact frozen digest>`. Returned versions and lengths are checked before reading, and every included original must finish with its expected SHA-256 and length. Missing objects retain explicit `OMITTED` inventory entries. Integrity failure produces an incomplete ZIP and aborts the response rather than an apparently complete archive.

Recipient exports preserve only the grant's projected JSON and selected representations. Reviewed derivative exports include the derivative digest while withholding the original digest and storage lineage. The same grant identity, version, fields, and media selections are checked before every ZIP chunk, including JSON and the final directory. Late revocation or a scope change aborts the response. Previously delivered bytes cannot be recalled; a client disconnect closes the current storage iterator promptly.

Canonical packages also include `proof-supplements.json`, with schema `packproof.signed-supplement-snapshot.v1`. It freezes `proofId`, `coreManifestSha256`, ordered signed records and exact `canonicalJson` strings, `sequence`, head `sha256`, `snapshotAt`, and the offline snapshot limitation when the stream is created. Both `package.json.sources.signedSupplements` and `archive.json.sources.signedSupplements` identify its path, sequence, head digest, and snapshot date. Its file bytes are included in the hash inventory. A later supplement does not silently enter an already-created export. The separately verified signed chain does not extend the root signature to legacy `shipping.json` or `events.json`, and it cannot prove that no unseen later records exist. Scoped public packages do not disclose this participant snapshot.

The archive audit event is `ARCHIVE_CONTENT_PREPARED`, with archive completion and delivery explicitly `UNCONFIRMED`. It occurs before the end-directory authorization checks and must not be counted as a completed download or recipient receipt. A regression disables the exporting account immediately after that event, verifies the response aborts without an end directory, and confirms that no success-named export event is recorded.

Validation covers an actual 12 MiB ZIP checked by Python's standard `zipfile` CRC reader, consumer disconnect cleanup, declared-limit rejection before a media pull, digest failure, pinned versions without whole-object reads, independent standalone PackProof verification, explicit omissions, in-flight revoke and scope narrowing, signed snapshot freezing, HTTP recipient scope boundaries, and all three lifecycle manifests. This verifies the streaming and archive contracts locally; deployment capacity remains subject to the separate measured load and hosted checks.
