## Runtime controls and rollback boundary

The canonical switch names are in `backend/src/intake/runtime-config.ts`. Change them through the existing service configuration/rollout mechanism; these are environment settings, not a new live feature-management service.

| Setting | Meaning / safe initial value |
| --- | --- |
| `PACKPROOF_INTAKE_ENABLED` | Master admission switch; enabled only by the exact string `true`. Leave unset/false for the compatibility deployment. |
| `PACKPROOF_INTAKE_ACTOR_IDS` | Comma-separated owner allowlist; empty by default. A true master switch alone does not enable an unlisted owner. |
| `PACKPROOF_INTAKE_HANDOFF` | Owner-approved device registration/new handoff delivery and acceptance admission; false initially. Recovery of an already accepted context remains distinct from new admission. |
| `PACKPROOF_INTAKE_BROWSER` | Browser-source admission; false initially. The separately disabled extension descriptor still requires real fixture validation. |
| `PACKPROOF_INTAKE_EMAIL` | Email-source setup/processing admission; false initially. Requires configured private ingress and validated templates before useful automatic intake. |
| `PACKPROOF_INTAKE_SHIPPO` | Merchant Orders ingestion; false initially. Merchant authorization and worker scope must also qualify. |
| `PACKPROOF_INTAKE_MAIL_DOMAIN` | Dedicated intake subdomain only; unset until verified. Do not reuse or alter the root mail domain. |

Mail worker configuration additionally uses `PACKPROOF_INTAKE_QUEUE_URL`, `PACKPROOF_INTAKE_RAW_BUCKET`, `PACKPROOF_INTAKE_TOPIC_ARN`, `PACKPROOF_INTAKE_RAW_PREFIX` (default `received/`) and the AWS region. These are resource identifiers, not permission to activate the SES rule or broad email forwarding. The root site/DNS and existing tracking credentials remain separate.

Deploy compatibility readers and durable guards with admissions disabled, apply additive migrations through the existing migration authority, then deploy inactive adapters and matching clients. Enable only the controlled owner after every active API instance understands the stored contract and the relevant real-source gates pass.

**Once a contract-v1 Proof exists, the compatibility release is the rollback floor.** Disabling admission cannot erase its cohort/contract, unpin its snapshot, relax finalization or interrupt accepted capture/upload recovery. Stop new source admissions and automatic triggers; retain queued receipts, raw sources, snapshots and evidence; finish or safely resume accepted captures. Do not downgrade to a pre-contract binary, drop populated schema or rewrite a manifest to bypass an error.

Before expanding the pilot, finish the final candidate CI and staged rollback, verify dedicated ingress/DLQ and resource permissions, configure an incremental cost alert, and document retention/cleanup for unlinked failed mail separately from Proof-bound sources. The staged raw-mail bucket intentionally has no blanket expiry that could delete a committed source; that protection is not an implemented seven-day cleanup policy.
