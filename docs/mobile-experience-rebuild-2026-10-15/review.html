Review these two journeys

  1. First manual Proof. Choose the fresh/new-seller scenario. Create a Proof, name the item, start and finish the recording simulation, review, explicitly confirm the declaration and simulated signing, then observe uploading, server receipt and finalization as distinct states.
  2. Recover a saved original. Choose failed or offline upload. Resume the existing Proof and recording, restore the simulated connection and retry. Compare it with the interrupted-recording scenario, where an incomplete take must not be treated as a complete continuous video.

Then inspect Proofs, Capture, Evidence, Shipment, History, Updates, Profile, Settings and Integrations. Use both themes and large text. All displayed data, camera frames, signing and uploads are simulations.

What the code audit established

  • The existing shared task, recovery and completion owners should be retained. A second evidence pipeline is unnecessary.
  • Capture renders queue filters/search even with no orders. Optional technical receipts occupy the main evidence composition.
  • Some unfinished deep links reach the viewer while list/notification entries use the resume resolver. A small intent adapter can close that gap.
  • Ordinary native packing uses one continuous video and explicit biometric signing. Grading and receiving have separate policy-driven photo requirements.
  • The current source already starts tracking collapsed and deduplicates the Home hero. Exact installed-build reproduction is needed before calling those current defects.
