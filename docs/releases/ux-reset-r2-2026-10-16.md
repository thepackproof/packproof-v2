# UX reset r2 release candidate

This candidate carries the reviewed capture, task progression and navigation fixes into the production clients.

## Behavior

- Active capture blocks route and Proof changes. Native camera Back offers keep recording, finish and review, or cancel as an interrupted take retained for recovery. Existing account-bound journals and server acceptance remain authoritative.
- Camera Back after manual creation opens the saved item information for the same Proof. Saving edits returns to camera without creating another Proof. Unsaved edits have an explicit save/discard choice. Integration screens preserve their originating workspace.
- Photo recovery derives remaining required slots. Complete photos offer review and submission; pending acceptance offers a submission check. A saved photo is not labeled as server-accepted evidence.
- Shared next-action priority: upload failures, pending photo submission, interrupted capture, unresolved server state, saved recording review, complete photos, partial photos, ordinary required tasks, confirmation, ready orders. Each class sorts by most recent Proof/draft update, then immutable ID. Healthy background uploads stay passive.
- Home emphasizes one action, Proofs exposes compact filters and optional search, and Activity avoids a second task catalog. Search inputs retain React identity; text and controls wrap without disabling font scaling.
- Existing exact-ID notification routing, fresh authorization, evidence hashing, upload idempotency and finalization controls are retained.

## Candidate identities

- Android: production profile version 1.0.1 / code 68 (signed AAB pipeline required).
- Desktop: 1.0.3 (Windows, Intel Mac and Apple Silicon signing pipeline required).
- Web: existing Sites project; patch applied to its current source separately to preserve newer website content and Worker behavior.

## Verification and promotion

Automated verification covers shared priority, completed-photo progression, account isolation, original retention, route context and blocked capture exits. Web and desktop TypeScript/build checks run locally. Native camera hardware, Android 200% font scaling, installation/upgrades and desktop platform acceptance are not established by these tests.

Production native promotion still requires the existing signing and exact-candidate acceptance gates. No gate, acceptance record, attestation, upload owner, or evidence policy is bypassed by this change. The Android AAB workflow builds an artifact; it does not publish to Google Play. Desktop production publication requires its exact-commit acceptance report and protected signing/publish environments.
