# Isolated M2 envelope acceptance

This one-shot harness is scoped to synthetic data in account `784514617543`, `us-east-1`, existing isolated VPC `vpc-0c4f12c0ba9393ae3`. It does not enable production routes, organization cohorts, workers, or migration 093. It does not represent device capture, an authenticated HTTP acceptance test, a merchant pilot, or independent human release approval.

The separate `packproof-m2-20261022-envelope` stack owns four new private versioned buckets, three P-256 keys, separate task/execution roles and managed secrets, and worker/restore task definitions. No services run continuously. Committed media, journal and artifact buckets enforce two-day COMPLIANCE default retention. The worker cannot change retention, delete versions, write originals, read secrets directly or sign root manifests. Its artifact adapter uses conditional creation and checks actual bytes and retention on the exact returned S3 version; a bucket default alone never constitutes a receipt. The dedicated restore role cannot sign or publish protected objects.

The owner-only controller creates `m2_integrity_20261022` and `m2_integrity_restore_20261022`, refusing pre-existing databases or logins. Migration 093 is confined to those new databases. Neither the M1 database nor its journal is reset. The synthetic fixture is an explicitly owner-seeded LEGACY_UNKNOWN blue MP4 finalized through the existing domain function. The script records this limitation in every configuration/receipt.

## Execution and evidence

1. Regenerate `envelope-acceptance-assets.json`; run cfn-lint, CloudFormation ValidateTemplate and review each change set. Keep existing M1 services at zero and its WriterFence CLOSED when resuming temporary compute/egress. Build the exact committed source using the existing image-only phase; resolve its immutable ECR digest.
2. Create the M2 stack with that digest, source, existing service security group and TemporaryBuildAuthority=true. The temporary attachment is only for the isolated owner build role. Run `envelope-control.buildspec` with M2_CONTROL=bootstrap, exact new stack output bindings, purpose `isolated-m2-synthetic` and the existing CodeBuild-injected owner secret. Never read or pass the secret through a tool response. Pin the returned runtime configuration S3 VersionId and SHA-256 into the task definitions.
3. Open only the M2 IAM writer fence and run the worker in probe mode. Verify actual original-version retention, conditional journal writes, allowed worker-key signing and denied root signing/deletion/retention/original writes/direct secret reads. Once its ready report is present, close the M2 IAM fence through CloudFormation, wait for completion, and write a fresh fence marker bound to that exact task ARN and source. The still-running task must demonstrate that its cached credentials can no longer publish or sign.
4. Independently inspect the deployed image, bucket/key/role configuration and completed probe. Only then write `acceptance/m2/config/protection.json`, schema `packproof.isolated-envelope-protection.v1`, with reviewer scope, short expiry, source/image/role/task bindings and the six tested protection booleans. Pin its exact version/hash. This receipt is operator evidence, not self-certification by the worker.
5. Reopen the M2 IAM fence and run mode=work with the protection pins. The worker requires a durable source/request journal, loses one response after actual artifact preservation, reconciles the first stored signature, waits for the result journal before READY and exports exact frozen manifest/media versions. Independently download and hash the private package and separately authenticated trust file; run the Python verifier with expected proof/manifest bindings. The internal export callback does not claim to test HTTP authorization.
6. Close the source database with the owner controller and close M2 IAM. Independently bind its final core/policy heads, NOLOGIN and writer-fence state to `acceptance/m2/config/source-closed.json`. Create the fresh restore target using M2_CONTROL=restore-bootstrap. Run the dedicated restore task with pinned configuration, protection, replay-input and source-close receipts. Check exact accepted envelope/core digests, no signing, and writers still disabled.
7. Close all M2 logins and stop outstanding tasks. Remove TemporaryBuildAuthority before pausing the M1 build role/egress. Keep M1 services at zero, WriterFence CLOSED and ComputeEnabled=false. Retain protected objects, public evidence, secrets, keys and logs. Do not delete or overwrite retained M1 or production evidence.

Required task override names are M2_MODE; M2_PROTECTION_VERSION/DIGEST; and for restore M2_HANDOFF_VERSION/DIGEST and M2_SOURCE_CLOSED_VERSION/DIGEST. Configuration pins and resource bindings are stack parameters/environment, not archive-provided trust roots. All evidence objects are private and versioned.

This document specifies the procedure. A cloud result must be separately recorded with actual task/build/change-set identifiers and downloaded artifact hashes; the presence of this harness does not mark acceptance passed.
